添加映射

留空则爱快 DNAT 的「外网端口」与内网端口一致（默认，也是你现有 QB/TR 映射的写法）。 这是爱快那一侧的端口，不是公网端口：填了内网端口，CGNAT 还会把它再翻成另一个公网端口， 对外发布一律用表格里的「公网访问地址」，那个是 STUN 实测值。 添加后会立即在爱快创建 DNAT 规则并触发一次探测。

批量录入（从 Lucky / 爱快粘贴）

直接在 Lucky 后台或爱快「穿透规则」页选中复制，粘进来即可。 每行一条，支持 名称 IP 端口 协议 和 IP:端口 连写， 也认爱快那种 UDP4 :39213 EasyTier-udp — — 192.168.6.42:27834 的整行格式。

行里的公网端口（如 :39213）会被丢弃：CGNAT 下爱快 DNAT 的外网端口 必须等于内网端口，把公网端口填进去规则就匹配不上了。 公网访问地址会在录入后由 STUN 自己测出来。

从爱快导入已有规则

把路由上已有的 DNAT 规则直接登记进来，不会改动路由上的任何设置， 也不会删掉重建——沿用原有的规则 ID、内网地址和外网端口。 接管后可统一管理、纳入自动对账； 只有目标机就是容器自己时才会顺带测出公网访问地址。

公网端口是怎么测出来的？

容器从目标机那个端口号往外发一个包。爱快保留源端口，这个包出去时外部口 也是同一个端口号，于是和目标机自己的流量共用 CGNAT 上同一条映射 —— 问 STUN 服务器 拿到的就是外部真正能连进来的那个端口。
实测：.104:24213 发包 → 公网 1638，从公网连 119.126.171.249:1638 直接通到 192.168.6.248:24213。
每分钟发一次同时是保活：CGNAT 的映射空闲几分钟就会被回收、换一个新端口， 容器持续发包，端口就不容易漂。
爱快上就是一条普普通通的端口映射：内网地址、内部端口原样不动， 外网端口默认等于内部端口，不引入任何额外端口，流量也完全不经过容器。

公网 IP 或公网端口变了，要自己改吗？

不用，全自动。容器每分钟测一轮（并行测，几十条也是一分钟测完）： 测到新的公网 IP 就更新顶部地址并推一条「公网 IP 变化」通知； 测到公网端口变了就更新那一行并推「公网端口变化」通知。
而且爱快那边完全不用动 —— 爱快的外网端口固定等于内部端口， 公网端口怎么漂都与爱快无关，所以不需要你触发任何操作。 真要改的只有对端：把新的公网访问地址发给对方，或者配好 通知/Webhook让它自动推给你。

全自动，什么都不用装

容器从目标机那个端口号往外发包 —— 爱快保留源端口，出去时外部口也是同一个号， 于是和目标机自己的流量共用 CGNAT 上同一条映射，测出来的就是外部真正能连进来的端口。 所以每台内网机器都不用装任何东西，容器自己就能把全部映射测出来。

要守住三条，测出来的地址才真的能用：
  1. 按协议挑服务器 —— CGNAT 上 TCP 与 UDP 是两套端口， UDP 测出的端口 TCP 连不进来（实测 UDP 测出 1767，TCP 连 1767 完全不通）。
  2. 每条映射固定同一台服务器 —— 换一台就是新开一条流、拿到一个新公网端口， 旧的还没老化，外部连进来 CGNAT 不知道往哪送。
  3. 保持住 TCP 连接 + keepalive —— CGNAT 是每条新连接一个新公网端口， 重连就换号（实测整块从 32xx 跳到 40xx）；同一条连接上每 20 秒问一次则纹丝不动。

变更通知（Webhook）

公网 IP 或公网端口一变就推送给你 —— 这就是 Lucky 里「STUN 穿透 + Webhook 推送」那套。

CGNAT 的公网端口会自己漂移（实测同一端口隔 75 秒就换一个）， 所以「公网端口变化」必须带冷却，否则一条映射就能把手机刷爆。 默认同一映射 10 分钟内只推一次。

地址只需填到路由地址（如 https://192.168.6.254）， 程序会自动补 /api/v4.0。
